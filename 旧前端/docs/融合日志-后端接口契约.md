## 2. 与指南的差异（照抄会踩的坑）

| 指南写法 | 本项目实际 | 怎么办 |
|---|---|---|
| Spring Boot 3 | **Spring Boot 4.0.6** | 语法基本兼容，但注意 Jackson 换成了 3 |
| `import com.fasterxml.jackson.databind.ObjectMapper` | Jackson 3：`tools.jackson.databind.ObjectMapper` | 沿用 `LogRepository` 里已有的写法，否则编译不过 |
| `spring-boot-starter-validation` 的 `@Valid @Size @Pattern` | **pom 里没有这个依赖** | 参数校验自己写显式判断（本文档第 5.3 节给法），或先加依赖 |
| `flyway-mysql` 管表 | **没有 Flyway** | 把 SQL 放 `docs/sql/` 或 `src/main/resources/db/migration/`，手工执行并留档 |
| `NamedParameterJdbcTemplate` | 随 `spring-boot-starter-jdbc` 一起在类路径上，**可以直接用**（`LogRepository` 用的是 `JdbcTemplate`，两者可共存） | 动态参数的查询建议用 `NamedParameterJdbcTemplate` |
| 一条 `UNION ALL` 七张大表做总览 | 实际是 **12 张表跨两个库** | 用 `audit_log_index` 索引表，见第 3 节 |
| 七张表加技术字段 | 七张表确实都在，但**没有主键**，且 Python 导入脚本会校验"列必须完全一致" | 见第 5.1 与第 8 节，只改验证函数不够 |
| `ingested_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6)` | JDBC URL 写了 `serverTimezone=Asia/Shanghai`，而 `event_time` 是 Java 按 **UTC** 写进 `DATETIME` 的 | **不要**用默认值。两种时间基准混在一列里，"今日/近 5 分钟"会差 8 小时，见 5.1 |
| 统一响应 `{code,message,data}` | 现有接口没有统一结构（日志接口返回空 200，心跳返回 `pong`） | 只让**新增的 `/api/v1/logs/...` 查询接口**用统一结构，既有写入接口不动 |
| SSE 直接推 `LogOverviewRow` | 一致，但**事件名必须是 `log`**，且 SSE 的 data 不能再包 `{code,message,data}` | 见 6.6，这是最容易接错的一处 |

## 3. 需要先定的一个决策：总览覆盖 7 张表还是 12 张

现状是 **7 张 Linux audit 表 + 5 张 Windows 事件表**，而指南的
`audit_log_index` 只按 7 类 audit 日志设计。这决定了后端工作量，**前端不关心这个选择**
（表格的列完全由 `/categories` 元数据驱动），但"融合总览里有没有 Windows 日志"取决于它。

### 方案 A（推荐，第一版就做这个）

总览只覆盖 **7 张 Linux audit 表**，`audit_log_index.category` 只有 7 个取值。

- 与指南、与前端当前 mock 完全一致；
- `os_type` 恒为 `Linux`，前端"系统类型"下拉里的 Windows 会查出空列表（正常，前端能正确显示空态）；
- 工作量可控：一张索引表 + 8 个接口。

### 方案 B（后续扩展，Windows 也进融合总览）

需要额外做三件事：

1. 给 5 张 Windows 表加 `source_client_id`（当前 `client_id` 被拼进了 `source_file`，
   形如 `fluent-bit://fb-win-001/Security`），并回填历史数据；
2. 定义 Windows 事件到统一字段的映射（草案）：

   | 统一字段 | Windows 来源 |
   |---|---|
   | `event_time` | `time_created` |
   | `event_id` | `event_id`（已是 VARCHAR，需转 BIGINT） |
   | `type` | `channel`（如 `Security`、`System`），或 `provider_name` |
   | `hostname` | `computer` |
   | `os_type` | 固定 `Windows` |
   | `result` | 由 `level` 映射（`Error`→failed，`Warning`→warn，其余→success） |
   | `summary` | 入库时由 `eventdata` 生成短摘要 |
   | `source_client_id` | 新增列，来自归一化结果的 `client_id` |
   | `category` | 新增 5 个类别键（如 `win_security`、`win_system`…） |

3. `/categories` 多返回 5 个类别。前端会自动多出 5 个标签页与对应的动态列，**前端零改动**。

**建议**：先按方案 A 交付，方案 B 等 A 跑顺了再评估。本文档其余部分都按方案 A 写。

## 4. 通用约定

### 4.1 统一响应结构（仅用于新增的日志查询接口）

```json
{ "code": 0, "message": "success", "data": {} }
```

- `code = 0` 成功，前端只取 `data`；`code != 0` 或 HTTP 4xx/5xx 时
  **`message` 会原样显示给运维人员**，请写中文可读文案，例如
  `"不支持的日志类别：win_security"`，不要写异常类名或 SQL。
- 既有写入接口（`/api/v1/logs/windows`、`/api/v1/logs/linux`、`/api/v1/heartbeat`）
  **返回值保持原样**，Fluent Bit 依赖现有行为。
- 前端超时 8 秒（导出下载 120 秒）。

响应类建议放在公共包，两个模块共用（心跳契约里已提过同一个类）：

```java
package com.inspection.logbackend.web;

public record ApiResponse<T>(int code, String message, T data) {
    public static <T> ApiResponse<T> ok(T data) { return new ApiResponse<>(0, "success", data); }
    public static <T> ApiResponse<T> fail(int code, String message) { return new ApiResponse<>(code, message, null); }
}
```

异常兜底（**限定包名**，否则会影响既有接口的错误响应）：

```java
package com.inspection.logbackend.web;

@RestControllerAdvice(basePackages = "com.inspection.logbackend.logs.controller")
public class LogsExceptionHandler {

    @ExceptionHandler(IllegalArgumentException.class)
    public ResponseEntity<ApiResponse<Void>> handleBadRequest(IllegalArgumentException e) {
        return ResponseEntity.badRequest().body(ApiResponse.fail(400, e.getMessage()));
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<ApiResponse<Void>> handleServerError(Exception e) {
        log.error("日志查询接口异常", e);
        // 不要把 SQL、堆栈、库名返回给前端
        return ResponseEntity.status(500).body(ApiResponse.fail(500, "查询失败，请查看后端日志"));
    }
}
```

### 4.2 时间、命名与取值

| 项 | 约定 |
|---|---|
| 时间格式 | **UTC ISO 8601**，如 `2026-10-07T07:10:41Z`；前端负责转本地时区显示 |
| 请求时间参数 | 前端发 `startTime` / `endTime`，值是带时区的 ISO 8601（例如 `2026-10-07T07:00:00.000Z`） |
| 字段命名 | JSON 一律小驼峰 `camelCase`；数据库列名下划线，转换在后端做 |
| 空值 | 用 `null`，不要 `""`，不要 `"-"` |
| 分页 | `page` **从 1 开始**（Spring/MyBatis 内部通常从 0 开始，自己做减法或偏移） |
| 分页上限 | `size` 默认 50，**最大 100**（前端下拉只有 20 / 50 / 100） |
| 布尔 | `true` / `false` |
| 枚举 | 见 4.3，只返回英文枚举，中文展示由前端映射 |

### 4.3 枚举

**七个类别键**（`category`，与数据库表名一一对应，前端的标签页与列都按它驱动）：

| category | 中文 | 表 |
|---|---|---|
| `authentication_session` | 认证与会话 | `log-linux`.`authentication_session` |
| `account_security_change` | 账号与安全属性变更 | `log-linux`.`account_security_change` |
| `process_command_execution` | 进程与命令执行 | `log-linux`.`process_command_execution` |
| `file_object_access` | 文件与对象访问 | `log-linux`.`file_object_access` |
| `network_ipc_communication` | 网络与 IPC 通信 | `log-linux`.`network_ipc_communication` |
| `system_service_audit_lifecycle` | 系统、服务与审计生命周期 | `log-linux`.`system_service_audit_lifecycle` |
| `security_policy_config_change` | 安全策略与配置变更 | `log-linux`.`security_policy_config_change` |

**字段类型 `type`**：`STRING` / `TEXT` / `LONG` / `INTEGER` / `DATETIME`。
前端按它决定筛选控件（数字用数字输入框、时间用日期选择器、其余文本）与展示格式。

**查询操作符 `operator`**：`EQ` / `CONTAINS` / `STARTS_WITH` / `GT` / `GTE` / `LT` / `LTE`。
第一版前端只用 `CONTAINS`（字符串）和 `EQ`（数字、时间），其余可以只在后端预留。

**结果 `result`**：`success` / `failed` / `denied`（前端映射为 成功 / 失败 / 拒绝，未知值原样显示）。

### 5.1 建表与字段变更

放 `D:\log-backend\docs\sql\`（或 `src/main/resources/db/migration/`），手工执行并留档。

**(1) 监控库 + 总览索引表**

```sql
CREATE DATABASE IF NOT EXISTS `log_monitor`
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE TABLE IF NOT EXISTS `log_monitor`.`audit_log_index` (

    KEY idx_ingested_id (ingested_at, id),
```

**(2) 七张 audit 表加技术字段**（每张表一条，示例给第一张）

```sql
ALTER TABLE `log-linux`.`authentication_session`
    ADD COLUMN `id`               BIGINT      NOT NULL AUTO_INCREMENT FIRST,
    ADD COLUMN `source_client_id` VARCHAR(64) NULL AFTER `tips`,
    ADD COLUMN `source_ip`        VARCHAR(45) NULL AFTER `source_client_id`,
    ADD COLUMN `ingested_at`      DATETIME(6) NULL AFTER `source_ip`,
    ADD PRIMARY KEY (`id`),
    ADD KEY `idx_event_time_id` (`event_time`, `id`),
    ADD KEY `idx_client_ingested` (`source_client_id`, `ingested_at`);
```

其余六张表执行同样变更。注意三点：

- 七张表**现在没有主键**（Python 建表时只建了普通索引），所以 `ADD PRIMARY KEY` 可以直接加；
  若 MySQL 报 "there can be only one auto column and it must be defined as a key"，
  把 `ADD COLUMN` 和 `ADD PRIMARY KEY` 拆成两条执行。
- **这个 `id` 是存证模块的前置条件**（存证表用 `normalized_row_id` 指向它），
  建议先把本条 DDL 执行完再做存证模块，详见第 11 节。
- `ingested_at` **故意不给 `DEFAULT CURRENT_TIMESTAMP(6)`**：
  JDBC URL 的 `serverTimezone=Asia/Shanghai` 会让默认值写入**会话时区的当地时间**，
  而 `event_time` 是 `LogRepository.setTimestamp()` 按 **UTC** 写进去的。
  两种基准混在一列里，`WHERE ingested_at >= UTC_TIMESTAMP(6) - INTERVAL 5 MINUTE`
  这类判断会**差 8 小时**（把一天的日志全算成"近 5 分钟"，或反过来查不到）。
  统一做法：**由 Java 显式写 UTC**，见 5.8。

### 5.4 总览查询（`audit_log_index`）

```java
@Repository
@RequiredArgsConstructor
public class AuditLogIndexRepository {

    private final NamedParameterJdbcTemplate jdbc;

    private static final String BASE_COLUMNS = """
            id, category_row_id, event_time, category, type,
            hostname, os_type, source_ip, result, summary, ingested_at
            """;

    public List<LogOverviewRow> findOverview(OverviewQuery query) {
        StringBuilder sql = new StringBuilder(
                "SELECT " + BASE_COLUMNS + " FROM `log_monitor`.`audit_log_index` WHERE 1 = 1 ");
        MapSqlParameterSource params = new MapSqlParameterSource();

        appendTimeRange(sql, params, query);
        appendHostFilter(sql, params, query.host(), "hostname");
        if (StringUtils.hasText(query.osType())) {
            sql.append(" AND os_type = :osType ");
            params.addValue("osType", query.osType());
        }
        sql.append(" ORDER BY event_time DESC, id DESC LIMIT :limit OFFSET :offset ");
        params.addValue("limit", query.size());
        params.addValue("offset", (query.page() - 1) * query.size());
        return jdbc.query(sql.toString(), params, OVERVIEW_ROW_MAPPER);
    }

    /** 主机搜索同时匹配 hostname / source_ip / source_client_id（指南 5.3） */
    private void appendHostFilter(StringBuilder sql, MapSqlParameterSource params,
                                  String host, String column) {
        if (!StringUtils.hasText(host)) return;
        sql.append(" AND (").append(column).append(" LIKE :host ESCAPE '\\\\' ")
           .append(" OR source_ip LIKE :host ESCAPE '\\\\' ")
           .append(" OR source_client_id LIKE :host ESCAPE '\\\\') ");
        params.addValue("host", "%" + SqlLikeEscaper.escape(host) + "%");
    }
}
```

要点：

- **`COUNT(*)` 必须用完全相同的 WHERE 条件**，不要为了省代码把全部数据查回 Java 再分页。
- 主机过滤只允许上面这三个固定列，绝不接受前端传入列名。
- `LIKE` 的 `%`、`_`、反斜杠要用 `SqlLikeEscaper` 转义，避免用户输入扩大匹配范围。
- 默认时间范围：不传 `startTime`/`endTime` 时按**最近 24 小时**处理（`Instant.now().minus(24, HOURS)`）。
  前端不会自动补"到此刻为止"的结束时间，就是为了避免把实时写入的新日志挡在窗口外。

### 5.5 分类动态查询

```java
public PageResponse<Map<String, Object>> findCategory(LogCategoryDefinition category, CategoryQuery query) {
    String selectedColumns = category.getFields().values().stream()
            .map(FieldDefinition::column)
            .collect(Collectors.joining(", "));

    StringBuilder sql = new StringBuilder()
            .append("SELECT id, ").append(selectedColumns)
            .append(" FROM ").append(qualified(category.getTableName()))
            .append(" WHERE 1 = 1 ");
    MapSqlParameterSource params = new MapSqlParameterSource();
    appendTimeRange(sql, params, query);

    if (StringUtils.hasText(query.field()) && StringUtils.hasText(query.value())) {
        FieldDefinition field = category.requireSearchableField(query.field());
        appendOperator(sql, params, field, query.operator(), query.value());
    }
    sql.append(" ORDER BY event_time DESC, id DESC LIMIT :limit OFFSET :offset ");
    params.addValue("limit", query.size());
    params.addValue("offset", (query.page() - 1) * query.size());

    List<Map<String, Object>> records = jdbc.queryForList(sql.toString(), params);
    long total = countWithSameConditions(category, query);
    return new PageResponse<>(records, query.page(), query.size(), total);
}
```

`appendOperator` 按白名单字段的类型拼操作符（片段）：

```java
switch (operator) {
    case EQ -> { sql.append(" AND ").append(column).append(" = :fieldValue "); params.addValue(...); }
    case CONTAINS -> {
        if (!field.type().supportsTextSearch()) {
            throw new IllegalArgumentException("CONTAINS 只能用于字符串字段：" + field.column());
        }
        if (rawValue.length() > 200) throw new IllegalArgumentException("模糊查询内容过长");
        sql.append(" AND ").append(column).append(" LIKE :fieldValue ESCAPE '\\\\' ");
        params.addValue("fieldValue", "%" + SqlLikeEscaper.escape(rawValue) + "%");
    }
    default -> appendComparison(sql, params, field, operator, rawValue); // GT/GTE/LT/LTE
}
```

**拼进 SQL 的表名与列名全部来自 `LogCategoryDefinition`**，用户输入的 `value` 始终参数绑定。
`qualified()` 用 `` `库名`.`表名` ``（`log-linux` 带连字符，必须反引号；JDBC URL 又没有默认库）。

```java
@Service
@Slf4j
public class AuditLogStreamService {

    private final Map<String, SseEmitter> emitters = new ConcurrentHashMap<>();

    public SseEmitter subscribe() {
        String id = UUID.randomUUID().toString();
        SseEmitter emitter = new SseEmitter(0L);   // 不超时，靠心跳保活
        emitters.put(id, emitter);

        Runnable remove = () -> emitters.remove(id);
        emitter.onCompletion(remove);
        emitter.onTimeout(remove);
        emitter.onError(error -> remove.run());

        // 事件名固定为 connected / log / heartbeat，前端按名字监听
        send(emitter, "connected", Map.of("serverTime", Instant.now()));
        return emitter;
    }

    /** 只发布事务已提交的日志 */
    public void publish(LogOverviewRow row) {
        emitters.forEach((id, emitter) -> {
            try {
                emitter.send(SseEmitter.event().id(String.valueOf(row.id())).name("log").data(row));
            } catch (Exception ex) {
                emitter.complete();
                emitters.remove(id);
            }
        });
    }

    /** 15~30 秒一次心跳，防止 Nginx/代理把空闲连接掐掉 */
    @Scheduled(fixedDelay = 20_000)
    public void heartbeat() {
        emitters.forEach((id, emitter) -> {
            try {
                emitter.send(SseEmitter.event().name("heartbeat").data(Map.of("serverTime", Instant.now())));
            } catch (Exception ex) {
                emitter.complete();
                emitters.remove(id);
            }
        });
    }
}
```

**三个必须注意的点（接错就看不到实时日志）：**

1. **事件名必须是 `log`**。前端的监听代码是 `source.addEventListener('log', ...)`、
   `addEventListener('connected', ...)`、`addEventListener('heartbeat', ...)`，
   名字不匹配浏览器不会交给页面。
2. **`log` 事件的 data 就是一行总览数据本身**（6.3 的 `items` 元素结构，camelCase），
   **不要再包一层 `{code, message, data}`**。前端拿到后直接 `JSON.parse(event.data)` 当行使用。
3. **必须在事务提交后发布**，否则页面会显示数据库里最终回滚的日志：

### 5.9 顶部统计（`/summary`）

**不要**让每个浏览器每 5 秒去 `COUNT(*)` 大表。做法：每分钟算一次，缓存到内存，接口读缓存。

```java
@Service
@Slf4j
public class AuditLogSummaryService {

    private volatile LogSummaryResponse cached = LogSummaryResponse.empty();

    @Scheduled(cron = "0 * * * * *")   // 每分钟
    public void refresh() {
        Instant now = Instant.now();
        Instant dayStart = LocalDate.now(ZoneOffset.UTC).atStartOfDay().toInstant(ZoneOffset.UTC);

        long todayTotal = countBetween(dayStart, now);
        long last5m = countBetween(now.minus(5, MINUTES), now);
        long activeHosts = countDistinctHosts(now.minus(5, MINUTES), now);
        Instant lastReceived = maxIngestedAt(10);
        long managedHosts = collectorClientRepository.count();   // 心跳模块的表；没有就先返回 hosts 去重数

        cached = new LogSummaryResponse(todayTotal, growthRate(todayTotal), last5m,
                last5m / 300.0, activeHosts, managedHosts, "RUNNING", lastReceived);
    }
}
```

- `countBetween` 走 `audit_log_index` 的 `(ingested_at, id)` 索引，一分钟一次完全没问题；
  数据量再大就改成"按分钟增量计数表"或 Redis 计数器。
- `todayGrowthRate` 可以先用固定值或与昨日同比；前端只做展示，缺失不影响。
- `pipelineStatus`：正常返回 `RUNNING`；采集链路异常时返回 `DEGRADED` / `STOPPED`（前端会显示"管道降级/已停止"）。

### 5.10 导出任务

只有**结果集 > 5000 条**时前端才走这条路径（≤5000 条由前端逐页拉取后自己生成 CSV）。
所以即使第一版不实现，页面在 5000 条以内也能正常导出。

```java
@Service
@Slf4j
public class AuditLogExportService {

    private final Map<String, ExportTask> tasks = new ConcurrentHashMap<>();
    private final ExecutorService executor = Executors.newFixedThreadPool(2);

    public ExportTask create(ExportRequest request, String operator) {
        String taskId = "exp-" + System.currentTimeMillis() + "-" + UUID.randomUUID().toString().substring(0, 8);
        ExportTask task = ExportTask.pending(taskId, request, operator, Instant.now());
        tasks.put(taskId, task);
        executor.submit(() -> run(task));
        return task;
    }

    private void run(ExportTask task) {
        task.markRunning();
        try (Writer writer = Files.newBufferedWriter(task.file(), StandardCharsets.UTF_8)) {
            writer.write('\ufeff');                       // UTF-8 BOM，Excel 打开中文不乱码
            writeHeader(writer, task);
            long rows = streamRows(task, writer);          // 按同一套 WHERE 条件流式读，别一次 load 进内存
            task.markCompleted(rows, "/v1/logs/exports/" + task.taskId() + "/download");
        } catch (Exception e) {
            log.error("导出任务失败 {}", task.taskId(), e);
            task.markFailed("导出失败：" + e.getMessage());   // 不要把 SQL / 库名 / 密码放进去
        }
    }
}
```

导出任务要记录（指南 10.2）：创建人、创建时间、类别与查询条件、导出条数、文件到期时间、下载审计。

### 6.6 GET /api/v1/logs/stream（SSE）

```
GET /api/v1/logs/stream
Accept: text/event-stream
```

服务端按顺序推送的事件：

| 事件名 | 时机 | data |
|---|---|---|
| `connected` | 建立连接后立即 | `{"serverTime":"2026-10-07T08:13:13Z"}` |
| `log` | 每有一条新日志入库并**提交后** | 6.3 里 `items` 元素的**原始结构**（camelCase，不包 `{code,message,data}`） |
| `heartbeat` | 每 15~30 秒 | `{"serverTime":"..."}` |

原始报文长这样（`\n\n` 分隔）：

```
event: connected
data: {"serverTime":"2026-10-07T08:13:13Z"}

event: log
data: {"id":3170,"categoryRowId":513,"eventTime":"2026-10-07T08:13:14.000Z","hostname":"audit-prod-01","osType":"Linux","category":"process_command_execution","categoryLabel":"进程与命令执行","type":"EXECVE","summary":"执行命令 sudo systemctl restart auditd","result":"success","sourceIp":"10.10.16.31","ingestedAt":"2026-10-07T08:13:14.100Z"}

```

前端行为：

- 用原生 `EventSource` 连接，**断线由浏览器自动重连**，后端不需要自己重连；
- 重连成功后前端会**重新查询第一页**补齐断线期间的数据，后端不需要补发历史事件；
- "暂停实时"只是前端不再插入列表，**不影响后端推送，也不影响采集**；
- 页面切到别的路由或关闭时，浏览器会断开连接，后端的 `onCompletion` 会清理 emitter。

Nginx 反代必须关掉缓冲，否则实时日志会被攒住：

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8080/api/;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_buffering off;
    proxy_read_timeout 3600s;
}
```

## 7. 前端已有的容错（后端不必额外做）

| 情况 | 前端行为 |
|---|---|
| 请求失败 / 超时（8 秒） | 顶部错误条 + 重试按钮，**保留上一次成功数据**，显示"数据更新时间" |
| 连续失败 ≥ 2 次 | 提示升级为"已连续 N 次查询失败" |
| 切换类别 | 自动取消上一个未完成的请求（`AbortController`），后端不必处理"客户端断开"以外的逻辑 |
| `code != 0` | 直接展示后端返回的 `message` |
| `/categories` 里没有 `shortLabel` / `count` | 用内置短名兜底，角标不显示 |
| `/categories/{c}` 没返回 `fields` | 用已加载的元数据字段 |
| 详情接口返回裸记录 | 自动识别（不需要 `{record, fields}` 包装） |
| `records` 缺少 `source_client_id` 等技术列 | 表格只显示元数据里的列，不报错 |
| SSE 断开 | 右上角显示"连接已断开"，浏览器自动重连，重连后自动补查第一页 |
| 导出任务迟迟不完成 | 轮询 2 分钟后提示"导出任务超时，请稍后重试" |
| 结果集 ≤ 5000 条 | **不调用** `/exports`，前端逐页拉取后自己生成 CSV（含公式注入防护） |

## 8. Python 导入脚本的兼容改动

`src/main/python/linux/import_audit_csv_to_mysql.py` 是历史 CSV 的导入脚本，
它现在会**拒绝**加了技术字段的表。第 208~220 行是精确比较：

```python
def validate_table_columns(cursor: Any, database: str) -> None:
    for table, expected in TABLE_COLUMNS.items():
        cursor.execute(
            "SELECT COLUMN_NAME FROM INFORMATION_SCHEMA.COLUMNS "
            "WHERE TABLE_SCHEMA=%s AND TABLE_NAME=%s ORDER BY ORDINAL_POSITION",
            (database, table),
        )
        actual = [row[0] for row in cursor.fetchall()]
        if actual != expected:                      # ← 加列后必然为真
            raise RuntimeError(
                f"Table {table!r} has an incompatible schema. "
                f"Expected columns: {expected}; actual columns: {actual}"
            )
```

改成"业务字段必须都在，允许技术字段额外存在"：

```python
def validate_table_columns(cursor: Any, database: str) -> None:
    for table, expected in TABLE_COLUMNS.items():
        cursor.execute(
            "SELECT COLUMN_NAME FROM INFORMATION_SCHEMA.COLUMNS "
            "WHERE TABLE_SCHEMA=%s AND TABLE_NAME=%s",
            (database, table),
        )
        actual = {row[0] for row in cursor.fetchall()}
        missing = [column for column in expected if column not in actual]
        if missing:
            raise RuntimeError(f"Table {table!r} is missing required columns: {missing}")
```

`insert_sql()` 用的是显式列名列表，所以 `id`、`ingested_at` 由 MySQL 自动生成，不用改。
但**历史数据导入完必须补 `audit_log_index`**，否则总览页看不到这些记录：

```sql
-- 七张表各执行一次，category 传对应的类别键
INSERT INTO `log_monitor`.`audit_log_index`
    (category, category_row_id, event_time, event_id, type,
     source_client_id, hostname, os_type, source_ip, result, summary, ingested_at)
SELECT 'authentication_session',
       t.id, t.event_time, COALESCE(t.event_id, 0), COALESCE(t.type, ''),
       t.source_client_id, t.hostname, 'Linux', t.source_ip, t.result,
       CONCAT(COALESCE(t.type, ''), ' ', COALESCE(t.operation, ''), ' ', COALESCE(t.account, '')),
       COALESCE(t.ingested_at, t.event_time)
FROM `log-linux`.`authentication_session` t
LEFT JOIN `log_monitor`.`audit_log_index` i
       ON i.category = 'authentication_session' AND i.category_row_id = t.id
WHERE i.id IS NULL;
```

`uk_category_row` 唯一键 + `LEFT JOIN ... IS NULL` 保证**可重复执行、不会插重**。
历史行的 `summary` 只能是拼接出来的降级版本，实时入库的行才有完整摘要。
历史 CSV 里没有 `client_id`，导入后 `source_client_id` 为空（按 NULL 处理，不计入任何主机）。

## 11. 与其它模块的关系（存证模块依赖本模块的 id）

本模块不是孤立的：`原始日志单条存证` 模块的记录要指向本模块分类表的行。
两个模块共用一套类别定义、共用一个库，**请按下面的方式复用，不要各写一份**：

```
   Fluent Bit ──▶ LogController 接收原始字节
                        │
                        │ 同一事务内
        ┌───────────────┴────────────────────────┐
        ▼                                        ▼
  `log-linux`.七张分类表                  `log_monitor`.audit_log_evidence
  （本模块：**必须补 id 主键**）            （存证模块：raw_hash + 文件位置
        │                                   + normalized_row_id → 分类表 id）
        ▼
  `log_monitor`.audit_log_index
  （本模块：总览检索索引）
```

三条硬约束：

1. **本模块 §5.1 给七张分类表加 `id` 主键，是存证模块的前置条件。**
   存证表用 `(normalized_table, normalized_row_id)` 关联融合行，
   没有 `id` 就无法建立可靠关联。建议**先合并并执行本模块的 DDL**，再开始做存证模块。
   过渡期存证侧可以先写 `NULL`，等 id 补好后再回填。

2. **类别枚举只应有一份权威定义。** 本模块的 `LogCategoryDefinition`（含表名、字段白名单、
   中文标签）是超集，存证模块只需要"键 + 中文名"。建议把两者合并为一个枚举
   （例如 `com.inspection.logbackend.logs.config.AuditLogCategory`），
   存证模块引用它，避免以后新增类别时两处漂移。

3. **时间基准要一致。** 分类表的 `ingested_at`（本模块）与存证表的 `received_at`（存证模块）
   是同一次接收的两个时间点，通常相差几毫秒：融合统计用 `ingested_at`，
   存证与"接收延迟"分析用 `received_at`。两者都必须由 **Java 显式写 UTC**，
   都不要依赖 `DEFAULT CURRENT_TIMESTAMP`（原因见 §5.1 的时区说明）。

另外，存证模块会改动 `RawLogFileWriter` 与 `LogIngestionService.ingest()` 这条链路：
原文留档之后、写分类表之前，多一步"按记录切分原始字节 + 算 SHA-256 + 写分段文件"。
**本模块的 `LogRepository.save()` 需要能返回每条的自增 id**（存证要写 `normalized_row_id`），
建议改成逐条 `GeneratedKeyHolder`；并注意 **JDBC URL 不要加 `rewriteBatchedStatements=true`**，
开了之后批量插入拿不到每条的 id。

     （**而且这里的 `MYSQL_HOST` 是 `100.107.214.72`，和 application.yml 的 `192.168.5.6` 不是同一台**，

2. **`application.yml` 的 JDBC URL 没有默认库**（`jdbc:mysql://192.168.5.6:3306/?...`），
   所有 SQL 必须写 `` `库名`.`表名` ``；`log-linux` 带连字符，漏了反引号会直接语法错误。

3. **`serverTimezone=Asia/Shanghai` 与 UTC 写入的并存**：`LogRepository.setTimestamp()`
   把 `event_time` 按 UTC 写进 `DATETIME`，而连接会话时区是 `+08:00`。
   只要所有时间比较都用 `UTC_TIMESTAMP()`（而不是 `NOW()`）就是一致的，
   但**不要**给新列用 `DEFAULT CURRENT_TIMESTAMP`，见 5.1。

4. **`HeartbeatWatchdog` 与心跳状态**：如果总览的"纳管主机数"要取自 `collector_client`，
   注意心跳模块目前还没落库（心跳只存在内存 `ConcurrentHashMap`），
   需要先按心跳契约把 `collector_client` 建起来；否则先返回日志里出现过的主机数。
